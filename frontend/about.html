$ about --engine

What runs when you hit Run scan.

$ how_it_works

01 · EXTRACT

Your .zip is unpacked in memory. Vendored directories (node_modules, .git, __pycache__, venv…), minified bundles and lockfiles are skipped so results stay signal, not noise.

02 · ANALYZE

Every source file is matched against 22 detection rules — regex-based static analysis tuned per language. Each hit records the file, line number and offending snippet.

03 · SCORE

Findings are weighted by severity — Critical −25, High −10, Medium −5, Low −2 — into a 0–100 security score with an A–F grade. The archive is deleted; only the findings report is kept.

$ detection_rules

The rule set the engine ships with today:

CRITICALExposed AWS Access Key

Matches AKIA… key patterns anywhere in the archive.

CRITICALExposed Private Key

Detects BEGIN PRIVATE KEY blocks committed to code.

HIGHSQL Injection

String-built queries, %-formatting and f-string SQL in execute calls.

HIGHEval / Exec Usage

Dynamic code execution primitives in Python and JavaScript.

HIGHShell Execution

os.system() and subprocess with shell=True.

HIGHDangerous innerHTML / document.write

XSS sinks that inject untrusted data into the DOM.

HIGHHardcoded Password / Secret

Credentials assigned as literals in source.

HIGHTLS Verification Disabled

verify=False — opens the door to MITM attacks.

HIGHInsecure Deserialization

pickle.loads on untrusted data → remote code execution.

MEDIUMHardcoded API Key

API keys and client secrets in source files.

MEDIUMWeak Password Hashing

hashlib.md5/sha1 used for passwords — use bcrypt/Argon2.

MEDIUMInsecure YAML Load

yaml.load() without a safe loader.

MEDIUMDebug Mode Enabled

debug=True leaking traces and consoles in prod.

MEDIUMWeak Randomness

random module used where secrets belongs.

MEDIUMSensitive Data in Local Storage

Tokens persisted where any page script can read them.

LOWInsecure File Handling

Files opened for writing without a context manager.
